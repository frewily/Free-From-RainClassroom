# 安卓授权返回与测试部署修复

日期：2026-11-01。当前开发包为 0.3.4（ARM64 分包版本号 2008）。本轮沿用原私有 GitHub／Cloudflare 应用与本人账号，未扩大账号权限、安装新依赖或操作生产资源。完整脱敏证据见[本轮记录](verification/client-s0-android-deployment-20261101.json)。

## 真机授权返回

一加 Ace5 至尊版、Android 16 上，原版在切到 Edge 后，手机回环返回通道曾超时，应用持续等待。0.3.1 仅增加授权期间的前台服务，仍未解决全部超时；0.3.2 将 HTTP 接收放到 Android 原生线程，保留 PKCE、state、Host、路径及单次接收校验。随后用户完成真实官方授权，报告账号已连接；助手通过 USB 观察本应用固定状态也确认已连接。0.3.3 中再次实际授权并连接成功。

接收器仅绑定 `127.0.0.1:8765`，不读取浏览器 Cookie，不记录或落盘授权码。原生接收有独立 10 分钟上限；临时前台服务有独立 12 分钟上限，完成、取消或移除任务时停止，不自启动。新增两项普通系统权限为 `FOREGROUND_SERVICE` 和 `FOREGROUND_SERVICE_SPECIAL_USE`。这些结果只覆盖本机实际流程，未证明具体厂商冻结机制或所有安卓设备均已兼容。

## 两个真实部署问题

首先，手机直连测试 `workers.dev` 地址失败，原逻辑因此不再提交空任务；Mac 经既有代理请求同一 Worker，严格比对合成响应成功。0.3.3 将手机检查限制为单次、最多 8 秒，失败如实展示，最终由 GitHub Runner 严格校验 Worker。云端任务仍核对 `ok`、`kind` 和本次随机实例值，手机请求失败不会被当成成功。

首份计划 `141eb6bd4e5da235` 确实部署了 Worker／工作流，并仅触发一次任务 [41285795738](https://github.com/frewily/rain-client-s0-target-20261027/actions/runs/41285795738)。任务失败于合成接口读取，安全错误摘要为 `HTTP Error 403: Forbidden`。应用正确展示失败，并回读确认入口关闭。之后经应用清理，工作流已移除，Worker 清空并保留，正常 Git／运行历史保留。

对同一地址做匿名对照，Python 默认请求标识收到 Cloudflare `403 / 1010`；明确的应用标识收到已关闭入口的 `404 / 1042`。0.3.4 为新工作流的 Python 请求增加 `RainClient-Deployment-Probe/1.0` 标识，不伪装浏览器或调整账号安全规则。计划保存工作流版本，旧记录按原始字节恢复，避免升级后因文件比对变化而无法安全清理。
