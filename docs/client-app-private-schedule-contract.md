# 私有课表同步与班级／课次匹配契约草案

日期：2026-11-11。源码基线：`1cf6b7ec7d1a2c8a70b9b7a62d0ada599bb38321`，与本轮 GitHub `main` 回读一致。

本文是下一阶段设计和开发切片建议，**尚未实现或部署**。推荐延续“雨课堂选班级＋手工时间／可选教务导入”，以用户自有 Worker／D1 保存版本化私有快照。先补稳定课次 ID 和本机待同步预览，再核验只读班级映射、实现私有同步，最后单独验收执行与启用。不要把本文中的拟定字段、路径或状态当成现有接口。

## 2. 四种标识与匹配边界

| 标识 | 表示什么 | 拟定用法 |
| --- | --- | --- |
| `courseId` | 雨课堂课程对象 | 可选显示元数据；不代替班级，不能解决同课多班 |
| `classroomId` | 用户选中的具体教学班 | 与 `origin`、`accountId` 共同确定选课归属 |
| `occurrenceId` | 本系统一条手工上课安排 | 本地生成并持久化；编辑日期／时间不变，删除后不复用 |
| `lessonId` | 雨课堂当前服务端课次 | 仅从已认证的当前课次读取结果中取得；不能由手工日期生成 |

目前**未确认** v3 当前课次响应中的哪个字段可可靠对应 v2 班级 ID，不在本草案中猜定 `classroomId`、`id` 或其他候选字段的含义。归档班级也不是历史课次；已加入列表、正在上课、历史记录、未来逐次课表继续分开验收。

后续管理模式的判定顺序拟为：

1. 读取并校验私有快照、账号归属和当前时间；配置错误或无有效窗口时停止，不能进入旧版“手动时段外单次检查”。
2. Runner 在自身环境中用所属 `SESSION` 只读确认雨课堂账号，与快照账号精确匹配。会话不交给 Worker 或助手。
3. 只读发现正在上课的课次，经过有证据支持的站点适配器，得到归一化的班级 ID／课次 ID 对。站点、角色和接口版本不跨站推用。
4. 按班级 ID 与该班自己的 `[开始, 结束)` 窗口匹配；名称、课程 ID、时间相近不能作为回退匹配。ID 仅按已核对的接口规则规范化，不擅自去前导零或改大小写。
5. 缺少可信班级映射、矛盾标识或多重候选时，该次匹配不进入业务链，也不标记已处理。正常匹配仍不代表获准签到、加入、答题或提交；执行功能另行验收。

这属于**新增显式管理模式**的设计，不在此次文档阶段修改旧模式的“筛选前仍可能进班”行为。未来集成必须单独测试：未选班级、未知映射和窗口外班级均不会调用任何课堂写入口。不能先靠进班响应取得身份再做选课判断。

### 只读映射核验怎么做

后续可在应用内增加一个固定 GET 资源 `/api/v3/classroom/on-lesson-upcoming-exam`，会话仍留在应用中；不调用现有组合函数 `get_listening_classes_and_sign()`。v3 的业务成功判据需核验，不能照搬 v2 的 `errcode` 判据。

仅保留字段是否存在、当前条数、与应用内已选班级的精确对应条数、缺失／冲突数量及适配器版本，不导出真实字段值、原始响应或凭据。必须有非空课次证据；“当前无课”只能记为本次为空，不能将映射标为通过。若主响应不能证明对应关系，再调查官方只读详情入口，不能猜 URL 或使用进班接口代替查询。

## 3. 待同步快照：拟定数据格式

以下全部是本项目拟定的协议字段和**合成示例**，不是雨课堂返回的字段：

```json
{
  "schemaVersion": 1,
  "subject": {
    "origin": "https://changjiang.yuketang.cn",
    "accountId": "account-synthetic"
  },
  "timezone": "Asia/Shanghai",
  "selectedClassroomIds": ["classroom-synthetic-a"],
  "occurrences": [
    {
      "occurrenceId": "mt_0123456789abcdef0123456789abcdef",
      "classroomId": "classroom-synthetic-a",
      "source": "manual",
      "date": "2026-11-16",
      "startMinute": 480,
      "endMinute": 580
    }
  ]
}
```

- 时间沿用 0.5.0 规则：北京时间 UTC+8、2000–2100 年、同日结束且结束晚于开始，最晚 23:59；每班最多 200 次，同班重复／重叠拒绝，相邻可保留。每周仍物化为具体日期。
- `occurrenceId` 拟为安全随机 128 位值加 `mt_` 前缀，并检查碰撞；跨班迁移应删除旧安排、新建 ID。ID 与日期／时间无关，不充当官方课次 ID。
- 所有出现的班级必须属于已保存选课；出现未知账号、未知时区、重复 ID、坏日期、坏记录、无法读取某一班级时整体不能成为可同步快照，不能跳过后再覆盖云端。
- 下一切片建议的快照预算为最多 100 个已选班级、2,000 次安排、UTF-8 编码后 256 KiB，任一超限都明确报错。这是本项目的拟定预算，不是平台额度；原有选课存储上限不改，不静默截断用户数据。
- 已选但无时间的班级单独列为待补项，普通发布先阻止；空选课／删除全部云端安排属于明确的清空操作，后续云端界面需展示影响并单独确认。
- 课程名、教师、原始学期、会话和 OAuth 信息不进入首版同步载荷；显示名称可在应用内用班级列表补充，未知名称不靠猜测补全。学期未知也不套用合工大编号。
- 同一班级的修改保留 `occurrenceId`，整份快照替换表达新增／修改／删除；跨班冲突先列出警告，由用户核对，不能自动取消其他班级。

### 本机迁移与一致性

v1 时间记录没有 ID。建议将完整校验后的 v1 记录复制迁移到独立 v2 记录，生成并回读稳定 ID；迁移失败不覆盖 v1、不显示已迁移。v2 存在但损坏时不能静默回退旧 v1，避免复活被修改或删除的旧安排。首版没有云端数据时可以安全完成该迁移；以后不能通过重新生成 ID“修复”已经同步的课次。

迁移后，编辑日期／时间仍须令 `dirty` 为真，比较不能只剩稳定 ID。全局快照读取与本账号的选课／时间写入走同一个串行协调器，构建前后复核会话及本地变更代数；任何半途变化或读取失败均不发布部分结果。页面保留上一份预览并标注过期，发布前代数不一致则重新预览。

## 4. 私有同步路线与认证

推荐业务管理 API 校验完整快照，再写用户自有 D1；Worker 内部调度和后续 Runner 读取相同版本。不是将当前公开 `data/course_schedule.json` 换个上传地址后继续原流程。

| 通路 | 拟定身份与权限边界 | 尚需验证 |
| --- | --- | --- |
| 手机管理课表 | 复用已有 Cloudflare 管理授权，在所属 D1 登记短期管理会话摘要；会话原值留手机，管理 API 只开放该实例的课表读／写和发布结果查询 | 引导、吊销与超时；不把历史 Cloudflare 成功当作新 API 已通过 |
| Worker 派发 Actions | 复用已有最小调度 GitHub App 身份，限目标仓库；与手机管理令牌分开 | 长期刷新、轮换持久化与并发，不重复注册 App |
| Runner 读取私有快照 | 优先采用 GitHub Actions OIDC；验证签名、固定 issuer、实例 audience、不可变仓库 ID、允许的 workflow/ref 和事件，使用签名内的 run ID／attempt | 官方支持不等于本项目已完成；离线验签、换钥／过期及受控合成任务另验 |
| Runner 读取雨课堂 | 该仓库自己的 `SESSION`，由应用在未来明确配置阶段直接加密写入 GitHub Secret | 当前客户端尚未接入这项写入；先核对实际权限与账号一致性 |

管理会话建议有效期 20 分钟，按实例和用途隔离，可撤销；它不包含 Cloudflare 或 GitHub 访问令牌，也不能触发任务、写 Secrets 或修改调度开关。首次雨课堂账号绑定来自应用内只读确认后的登记，不冒充雨课堂向 Worker 签发的身份凭证；Runner 仍要独立确认自己的账号。

OIDC 不需要新注册一个授权应用；未来工作流须显式增加 `id-token: write`，本轮不会改工作流。验证不能只解码 JWT，不能信任请求体自报的仓库／run ID，也不能把 JWT 提供的任意密钥 URL 当可信来源。若 OIDC 尚未实测通过，则运行读取接口不开放，不降级为把手机管理令牌交给 Runner。

**已知连通性门槛：** 0.3.4 时手机直连 `workers.dev` 曾失败，由 Runner 核验合成入口；该历史结果不能推定今天仍失败，也不能推定新管理 API 可达。真实同步前必须在手机内对拟定实例验证受保护管理通路。失败时保留本机草稿，不把私人课表塞进公开仓库、Actions inputs／日志或公共中转地址。自定义域名／DNS 如有必要应另列具体变更，不在本阶段默认执行。

直连 Cloudflare D1 REST API 是管理用途的备选，原管理授权已有相关权限的历史证据；但需要另验证原子发布、结果恢复与业务校验的位置，不能仅因接口叫 batch 就套用 Worker binding 的事务保证。本草案先选 Worker 管理 API，连通性未通过前不进入真实课表上传。

## 5. 发布版本、失败与并发契约

以下路径均为**拟定接口**，当前不存在：

| 请求 | 作用 | 判据 |
| --- | --- | --- |
| `GET /v1/instances/{id}/schedule` | 管理端读取当前版本和快照 | 返回 `revision`／ETag，私有响应 `no-store` |
| `PUT /v1/instances/{id}/schedule` | 原子发布一份完整快照 | 管理身份；必带 `If-Match` 与 `Idempotency-Key`；成功返回新 revision 与摘要 |
| `GET /v1/instances/{id}/publish-operations/{operationId}` | 核对超时／中断写入的结果 | 同实例管理身份；返回该操作的请求摘要与结果 revision |
| `GET /v1/instances/{id}/runtime-schedule` | Runner 读取必要快照 | 独立运行身份；无管理写能力；不能匿名读取 |

1. 实例先绑定 Cloudflare 账号、雨课堂站点／账号和不可变 GitHub 仓库 ID；普通发布不能重绑。客户端传入的 `subject` 必须与实例登记一致，不能凭请求体切换账号或任意目标 URL。
2. `revision` 由服务端产生、单调递增；未发布时为 0。发布是整体替换，不做静默字段合并。旧版本写入返回 412，保留本机草稿，刷新并展示差异；不自动强制覆盖。
3. 同一操作 ID 的重试必须使用持久化的同一份 UTF-8 请求字节。服务端对请求计算 SHA-256：同 ID 同内容返回原结果，同 ID 不同内容返回 409。客户端在响应前不能重新生成操作 ID 或重新序列化一个变化后的草稿。
4. D1 中的版本内容、当前版本指针与成功操作回执必须同一事务提交。拟使用 `schedule_heads`、`schedule_revisions`、`publish_operations`，管理会话另表。CAS 未命中不能只得到一次“更新 0 行但仍成功”的 batch；必须通过 SQL 约束／事务 guard 使其无发布效果，测试不能只模拟成功返回。
5. 连接超时、客户端退出或 Worker 等待超时均显示“结果待确认”，不显示成功或断言已回滚。先查同一操作回执并比摘要，再判断是否继续；不得直接另起一次发布。D1 等待超时不代表底层写入已取消。
6. 回执建议保留 14 天，客户端自动核对／重试上限 24 小时；超过期限先刷新当前版本、保留草稿人工核对，不能把过期回执的 404 当作“从未提交”。版本清理不得移除仍被当前指针或待核对操作引用的数据。
7. 身份失效时停止发布并保留本机数据，更新官方连接后再核对结果。错误响应只给固定安全分类，不返回 SQL、原始个人数据或凭据。未知 schema、未知站点和未知字段拒绝，不透传到执行端。

“已同步”与“已启用”分开。首次部署和成功发布都保持监听开关关闭，不继承旧 Worker 中 `AUTO_DISPATCH=true` 的值；关闭／开启监听是独立的明确操作。已有执行任务不因一次普通发布自动取消或重新发起。

## 6. 调度与执行端的后续接入约束

- 继续以课表时间触发，不让 Worker 持有雨课堂会话去全天发现课堂。拟沿用每 5 分钟调度检查及开始后 15 分钟补触发、且未到结束的门槛；云端配置缺失或无有效课表时不回退旧来源。
- dispatch 只携带实例、版本和不透明操作／安排标识，不携带私人课表、账号原值或会话。Runner 排队后启动时重新取当前有效版本，检查原触发安排是否已改期／删除及是否仍在窗口，过时请求不启动课堂业务。
- 单个任务通过启动检查后固定自己的运行快照；后续发布不宣称立即改变正在运行的任务。新开课／取消、重叠窗口和既有 concurrency 队列合并规则要在执行集成阶段用时间线验收，不能承诺修改即时生效。
- 判定必须逐班进行。若把同班相邻时段合并成连续窗口用于运行，仍保留原安排 ID；不能用其他班级的最大结束时间延长该班的许可窗口。同一已发现课次不因两个手工条目重复启动监听器。
- 两个 5 分钟周期、Actions 排队及环境准备都会影响首次发现；既有约 75 秒准备时间只是历史经验，排队没有本项目保证的上限。私有同步不会保证准点，也不能补回已错过的课堂消息。
- GitHub 接受 dispatch、Runner 启动、只读发现、进入监听及官方考勤是不同状态。KV 记录仍不代表严格单次执行或课堂成功；本阶段不重做去重架构。

## 7. 明确的下一开发切片：0.6.0 本机待同步快照

**推荐先实现本机快照，不部署云端。** 这是首次同步的输入准备，不是再次扩展时间编辑器的外观。

涉及文件建议：

- `apps/client/lib/timetable/manual_time*.dart`：稳定 ID、v1→v2 安全迁移、编辑时保留 ID 且正确判脏；保留旧记录。
- `apps/client/lib/courses/course_store.dart` 及新增账号级协调器：保存选课、保存时间与快照构建共用一致性边界，不跨账号串行阻塞。
- 新增 `schedule_snapshot.dart`／聚合控制器和待同步预览页：读取**全部已保存的已选班级**，不只当前归档开关下显示的那一份；缺项、错误、超限整体阻止。取消选课保留本机时间，但不进入当前快照。
- 增加合成 fixture 和相关 Flutter 测试，更新交接；不增加 Cloudflare、GitHub 写入或课堂请求。

验收标准：

1. 旧 v1 记录迁移后日期／分钟／归属不变；重开 ID 不变；失败不损坏 v1；损坏 v2 不自动回退。
2. 编辑同一课次保留 ID、改变数据并可保存；删除后新增不复用 ID；稳定 ID 碰撞及重复条目被拒绝。
3. 未归档、归档和当前列表未显示但已保存的选课一并核对；缺时间与读取失败分开显示，不自动省略。名称未知是显示限制，不假造名称／学期。
4. 构建过程中修改选课、修改时间、切换会话或晚到请求，不得形成混合账号或半份快照；变更后旧预览标为过期。
5. 页面准确显示待同步班级／课次数、日期／时区、阻塞项和警告；清空仅本机预览，状态始终为“尚未同步／启用监听”。不提供给助手／CLI 的真实快照导出。
6. 相关合成测试、静态分析、必要构建及应用内保存／恢复验证后，按约定更新文档、提交推送并核对远端。0.5.0 的历史验证不能替代新代码验证。
