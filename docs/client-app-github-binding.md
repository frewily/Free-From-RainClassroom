## 1. 这轮交付的行为

应用底部提供“雨课堂”“GitHub”两个入口，切换时保留各自状态。雨课堂登录沿用已验收实现；上轮窄屏显示调整随本次功能包带上，不为显示单独增加验收。

GitHub 的主流程：

1. 点击“绑定 GitHub”，应用向官方申请一次性代码。
2. 点击“复制代码并打开 GitHub”，在官方授权页输入代码、核对应用名称并授权，然后返回客户端。
3. 客户端按官方间隔自动查看结果，读取账号与本应用安装范围下的仓库；确认后加密保存本机连接。
4. 点击一个已授权仓库，只保存本机选择。该选择不代表已部署、写入配置或启用监听。
5. 重开时检查授权有效性、账号身份和最新仓库范围；被移除或归档的旧选择不再使用，也不会自动换选其他仓库。
6. “清除本机 GitHub 连接”删除本机授权和选择，不影响雨课堂登录；GitHub 官网撤销与云端停用仍是独立操作。

用户无需把一次性代码或令牌发给助手；本轮也不读取助手所用浏览器／CLI 的 GitHub 凭据。

## 3. 本机保存和失败处理

- 使用已有安全存储插件，独立命名空间 `top.frewily.rainclient.dev.github.manager`；不与雨课堂会话混存，不新增依赖或权限。
- 保存访问凭据、更新凭据及期限、账号 ID、应用 ID 和所选仓库 ID；不保存原始个人信息响应、邮箱或仓库详情响应。
- API 请求固定 HTTPS 官方域名，不跟随重定向；每次传输 20 秒上限、响应 1 MiB 上限。整个账号／仓库读取还有 45 秒上限；分页有总量和页数上限。
- 设备授权遵守官方轮询间隔，`slow_down` 后延长，网络故障退避；代码到期或用户取消后停止等待。
- 断网或未知 403 保留本机记录，明确失效要求重新授权。失效访问凭据在一次操作中至多尝试一次更新。
- 更新授权前先持久化“更新进行中”标记，再保存新的一对凭据。若响应丢失或保存未确认，重开不会重放旧更新凭据，改为请求重新授权。该保守降级不等于已验证所有云端轮换场景。
- 本机读写串行化，退出删除排在已经开始的保存之后。超时报告给界面，但不提前释放底层队列；旧请求、旧读取和旧超时均不能恢复或打断新操作。
- 本机记录损坏或读取失败时，界面仍保留明确的清除入口。清除失败可重试，不将未完成的清除显示为已退出。
