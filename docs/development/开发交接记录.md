## 4. 新对话优先工作包：雨课堂直接选课与课表来源调查

用户提出：既然软件已登录雨课堂，能否直接获取课程，让用户勾选需要监听的课程，减少学校教务登录和爬取，提升通用性。2026-11-01 已完成首轮只读调查，结论见第 7 节；下文保留调查问题与尚未完成的验证边界。

### 已核对的当前源码事实

- [config.py](../../config.py) 的 `get_listening` 指向 `api/v3/classroom/on-lesson-upcoming-exam`；[check_in.py](../../function/check_in.py) 的 `get_listening()` 读取 `onLessonClassrooms`，现有流程使用 `courseName` 和 `lessonId`。这证明代码接入了“正在上课”，不能证明已取得完整选课列表或未来课表。
- [course_schedule.py](../../function/course_schedule.py) 的 `fetch_schedule()` 登录合工大教务，取得每次课的日期、开始和结束时间。它还负责当前学期及时间窗口判定。
- [cloudflare/worker.js](../../cloudflare/worker.js) 用课表决定何时触发 Actions；[start.py](../../start.py) 用时间窗口决定何时检查／停止，在窗口内每 300 秒查询一次正在上课状态。因此“从哪里选课”和“何时启动监听”是两个问题。
- 当前课程筛选按名称；改为稳定课程 ID 匹配只是建议，具体课程／教学班／课次 ID 关系尚未验证。现有签到发生在监听筛选之前，未选课程也可能签到，不能静默改变这一行为。

### 建议的调查顺序与交付

1. 先读本地已有接口定义和资料，区分“完整已加入课程”“正在进行的课堂”“历史课堂”“未来开课安排”。不得把历史开始时间当作下一次上课时间。
2. 如需真实只读验证，在用户正常登录的应用／官方容器中使用该次会话，不从手机安全存储提取给助手或 CLI，不触发签到、加入课堂、答题或提交。只记录必要字段是否存在、分页／标识含义和脱敏结论，不留原始个人课表或响应。
3. 验证能否列出完整课程，以及课程 ID、教学班／学期、重名、分页、不同雨课堂站点是否可复用；仅测试当前 `changjiang.yuketang.cn` 不能宣称覆盖所有学校。
4. 验证有无可靠的未来日期及起止时间。若有，可评估雨课堂统一提供课程与课表；若无，比较“雨课堂选课 + 手工／可选教务时间”和“Worker 定期发现正在上课再启动 Actions”。
5. 对实时发现方案说明检查间隔、Actions 排队／启动耗时、开课早期消息可能错过、会话失效和请求频率；若 Worker 需要新持有雨课堂会话，也要明确凭据存储位置与当前仅本机保存的差异。不能把“手机登录成功”当成云端能长期自动发现课堂。
6. 交付一份基于证据的推荐、接口字段与边界、下一切片涉及文件及验收标准。调查后与用户确认实际路线，再接入课程选择、配置／私有课表或调度，不一次铺开所有未完成功能。

推荐倾向是让“选择哪些课”优先来自雨课堂，学校采集器作为可选能力；是否采纳及如何取得上课时间，等待实际证据和用户决定。这不是已批准的最终接口或数据模型。
