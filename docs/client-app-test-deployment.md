## 主人一次走完的操作

1. 覆盖安装 0.3.0，无需卸载或重测前两段。包名 `top.frewily.rainclient.dev`，分包版本号 2004，与上一版签名一致。
2. 在 Cloudflare 页点击“绑定 Cloudflare”，核对官方应用为 **Rain S0 Cloud Manager 20261028**、原五项权限和原本人账号；官方页收到结果后手动返回应用，应显示账号已连接。GitHub 页保持原空测试仓库选中。
3. 在“部署验证”点击“检查并生成测试部署清单”，核对随机 Worker 名、原测试仓库和单份工作流；点击“确认部署并运行空任务”，在应用内清单确认框中确认一次。
4. 保持应用前台查看进度。只有对应任务实际 `completed / success`，且测试入口关闭回读通过，才显示“测试链路已跑通”。无需回聊天索取代码、复制令牌或手动部署源码。

若排队超过观察窗口，应用保留本次进度，之后点“继续检查任务结果”，不再次触发。软件关闭期间无法保证及时关闭入口；重新打开继续检查或清理即可。本轮入口仅包含随机实例标识及合成健康状态，不返回个人信息。

通过后可按实际需要点击“清理本次测试”：删除本次仍与生成内容一致的工作流文件，关闭本次 Worker 公网入口、清空绑定并保留空 Worker。正常 Git 提交和运行历史保留，不清理其他资源。若文件或绑定被外部改动，停止并保留现场。

## 实现与验证摘要

- 复用既有 Flutter／Android 工具及插件；只将已有锁定缓存的 `crypto 3.0.8` 升为直接依赖，离线解析，其他包版本与摘要不变，无新增包下载或 Android 权限。
- PKCE S256 通过 RFC7636 向量测试；本机 HTTP 测试验证无效 state 拒绝、有效回调一次接收、重复回调不重放。回调仅绑定回环地址，带等待上限和清理，官方页面返回的真实手机行为待验收。
- 真实写入前先持久化意图；上传或创建响应丢失时只回读确认，派发结果未知时按独立工作流与提交定位运行，不盲目重发。
- 检查 run 的提交、工作流路径、事件及标题，再判断状态与结论。API 接受不算任务成功。入口关闭以当次 API 回读为准，已复现并修正“历史记录已关闭但外部重新开启”的回归。
- Worker 使用此前实测通过的 `application/javascript+module` 上传格式；已解析生成的工作流 YAML、内嵌 Python，Node 检查模块语法。合成预览已查看 320／390 像素布局，不作为真机或云端证据。
